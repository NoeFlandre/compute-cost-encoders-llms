# Grid’5000 operations

All project compute workloads run on reserved Grid’5000 nodes. Local execution
is limited to development checks, packaging, and control-plane work such as
checkout, submission, monitoring, and artifact publication.

This project follows the [Grid’5000 Usage Policy](https://www.grid5000.fr/w/Grid5000%3AUsagePolicy).
Use the official [Getting Started](https://www.grid5000.fr/w/Getting_Started)
and [Storage](https://www.grid5000.fr/w/Storage) guides for site-specific
access and storage details.
Run the policy check before and after every submission:

```bash
./scripts/grid5000/policy_check.sh
```

The setup phase has submitted no Grid’5000 jobs.

## Controlled submission

Use a site frontend for checkout and submission. Do not run the workload on the
frontend. The submission wrapper refuses duplicate active jobs with the same
run ID and defaults to one GPU for 30 minutes. Override the resource expression
only when the target site requires a different GPU property or queue:

```bash
export GRID5000_RUN_ID=smoke-001
export GRID5000_RESOURCES='host=1/gpu=1,walltime=0:30'
./scripts/grid5000/submit.sh \
  ./scripts/grid5000/run.sh -- uv run --locked python -m your_package
```

Before submission, set and pin these run inputs:

```bash
export GRID5000_CONFIG_PATH=configs/example.toml
export GRID5000_SEED=7
export GRID5000_DATASET_REVISION=dataset@revision
export GRID5000_MODEL_REVISION=model@revision
export GRID5000_CHECKPOINT_INTERVAL=100
export GRID5000_ARTIFACT_PREFIX=runs/smoke-001
```

The reserved-node wrapper records the source commit and configuration digest,
requires `uv run --locked`, uses node-local caches under `/tmp`, and rejects a
dirty checkout. It does not print credentials. Keep HF credentials in the HF
credential store or an environment variable; never put them in Git.

Monitor and cancel using the exact OAR job ID returned by `oarsub`:

```bash
./scripts/grid5000/status.sh JOB_ID
./scripts/grid5000/cancel.sh JOB_ID
```

## Checkpoints and artifacts

Every resumable checkpoint must carry a JSON metadata file with the source
commit, configuration revision, seed, dataset and model revisions, step,
metrics, `complete: true`, and a path in the project HF bucket. Validate it
before publication:

```bash
uv run --locked python scripts/grid5000/checkpoint_metadata.py \
  artifacts/smoke-001/checkpoint.json
```

Example metadata:

```json
{
  "source_commit": "<40-character-git-commit>",
  "config_revision": "sha256:<configuration-digest>",
  "seed": 7,
  "dataset_revision": "dataset@revision",
  "model_revision": "model@revision",
  "step": 120,
  "metrics": {"loss": 0.25},
  "complete": true,
  "artifact_uri": "hf://buckets/NoeFlandre/compute-cost-encoders-llms/runs/smoke-001"
}
```

Publish only after the job has produced and verified complete artifacts:

```bash
export GRID5000_PUBLISH_CONFIRM=yes
./scripts/grid5000/publish.sh artifacts/smoke-001 runs/smoke-001
```

The publication wrapper rejects credential-like files and requires the project
HF bucket. Important artifacts must be published before temporary Grid’5000
storage is cleaned. Cleanup is explicit and restricted to project-owned paths:

```bash
export GRID5000_CLEANUP_CONFIRM=yes
./scripts/grid5000/cleanup.sh
```

## Efficiency and completion

Request the smallest suitable node allocation and shortest realistic walltime.
Do not reserve resources speculatively or submit duplicates. Pin code,
dependencies, datasets, models, and seeds; checkpoint frequently; and verify
logs, metrics, checkpoints, final artifacts, and remote publication. Record the
exact job IDs and cancel any remaining jobs when the run is complete.
